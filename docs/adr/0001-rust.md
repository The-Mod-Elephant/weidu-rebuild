# ADR 0001: Implement the toolchain in Rust

- Status: Accepted
- Date: 2026-10-25

## Context

The toolchain parses untrusted binary files and applies untrusted instructions to a user's game
directory. The requirements are memory safety on hostile input, predictable performance on
I/O-heavy workloads, fast and safe text processing, one standard build on Windows, macOS and
Linux, and an approachable contributor experience. C and Rust were the candidates.

## Decision

Use Rust (edition 2024) in a Cargo workspace, with the compiler pinned in `rust-toolchain.toml`
and `unsafe_code` forbidden for every crate.

## Consequences

- Memory safety is enforced by the compiler instead of by review, sanitizers and fuzzing alone;
  out-of-bounds access on malformed files becomes an error value or, at worst, a panic, never
  memory corruption.
- The `regex` crate guarantees linear-time matching, which removes the denial-of-service risk of
  backtracking engines for mod-supplied patterns.
- Capability-based filesystem access is available as a maintained library (`cap-std`, see
  ADR 0003) rather than hand-written platform code.
- Cargo provides dependency management, cross-platform builds and tests out of the box; supply
  chain risk is handled with `Cargo.lock`, `cargo deny` and Dependabot.
- C would have required a separate build system, manual memory-safety discipline and more
  platform-specific code for the same guarantees.
