# ADR 0002: The Cargo package version is the version source

- Status: Accepted
- Date: 2026-10-25, revised for the release flow of #20 and the review of #23

## Context

Versions must follow SemVer 2.0.0, and a release must report the version it was published as.
A second, independently edited version source can drift from the first.

## Decision

- The `version` field in `Cargo.toml` is the application version. `iemod --version` reports it
  through `env!("CARGO_PKG_VERSION")`, and `default.nix` passes it to `buildRustPackage`.
- A release is made by setting `version` to the next SemVer 2.0.0 version in an ordinary pull
  request and, once it is on `main`, pushing the tag `v` followed by that version.
- Pushing the tag runs `.github/workflows/build.yaml` for that tag. Its `trigger-release` job
  starts `.github/workflows/release.yaml` on the same tag with the build's run ID, and that
  workflow publishes the build's artifacts as the GitHub Release for the tag.
- There is no `VERSION` file and no committed `CHANGELOG.md`; the release notes are generated by
  GitHub (`gh release create --generate-notes`).

## Consequences

- No bot needs write access to `main`, and no secret beyond the workflow token is required.
- Every build, not only release builds, reports the version in `Cargo.toml`.
- Nothing checks that the tag matches `Cargo.toml` or that the new version follows the SemVer rules
  for the changes since the previous tag; the maintainer checks both
  ([READINESS.md](../release/READINESS.md)).
